## A2：Apple系統認證視窗實測

Apple官方SDK的新callback物件提供custom scheme或HTTPS；舊初始化允許callbackURLScheme為nil。探針沒有自行發明scheme，而是由127.0.0.1 HTTP listener處理回呼，Apple系統認證視窗只負責呈現合成本機頁。使用ephemeral session，不需要既有cookies或帳戶。

| 測試 | 實際結果 |
| --- | --- |
| 2秒callback | 3.1秒自動接受；沒有人工切回app |
| 45秒callback | 45.3秒自動接受；沒有人工切回app |
| 取消 | 2.0秒記錄cancelled，同一取消路徑觸發 |
| 逾時 | 測試專用3秒期限於3.0秒記錄timeout |

四輪沒有app-background事件。取消／逾時由測試參數觸發，不是手指操作系統取消鈕；未另外做socket關閉探測。原始合成報告由Glance自身容器讀回，並非只看畫面就判定成功。

## C：相機初版、真實失敗與修正驗證

需求先寫入相機計畫，再實作中央ROI、4Hz本機樣本、清晰度／物件顯著性與目標匹配、約1秒穩定、單筆在途、最少4秒送出間隔、90秒／8項快取。背景、設定或暫停會取消並清記憶。相機不會在冷啟動自行打開，顯示的三欄仍固定由同一Pro模型提供。

C合成JSON圖測試成功：文字GLANCE 123；沒有條碼所以條碼欄空。模型請求4.801秒，含自然refresh及目錄查詢共8.427秒，successfulRefreshCount=1。這證明自然續期，不能當作live相機延遲。

本人第一次真相機試用沒有看到結果。後續只送一張的安全診斷證明：HTTP200、response.completed及JSON解析成功，用時3.642秒，結果含1個名称及4段文字；matchedAtCompletion=false、displayCount=0。因此問題在目標／顯示判定，不能說未擷取或空結果。没有查看、保存或複製該照片及原始文字，報告只保留計數。

修正集中在：特徵不確定時避免建立重複身份、保留在途anchor、稀疏細字清晰度取樣、小幅平移／曝光對齊。32項host測試及生成卡片控制器回放通過；回放涵蓋首次顯示、移開、回看、晚回隔離與取消。注入時鐘的3.75秒／1秒不是實際相機／網路時延。

新增只差一字標籤反例，發現低解析指紋可能合併兩者，已加入本機文字digest作身份否決條件。該文字不作顯示結果、不持久保存；Pro使用方式不變。模擬器Vision特徵不可用且文字摘要未取得，故反例的完整實機驗證仍未通過。不能把fixture略過或32項unit tests包裝成真相機已修好。
