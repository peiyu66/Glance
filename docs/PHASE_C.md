# C：可試用相機初版計畫

2026-10-09。使用者已明確要求繼續推進，必要實體操作才交回；本輪授權相機初版、離線／合成pipeline與既有iPhone驗收、文件／ProjectHub／Git／同Library更新。沿用已驗證Pro gpt-6-luna/none，不改billing或模型、不卸載清Keychain。

## 使用目標與待驗證假設

目標是讓本人拿起iPhone對準物品，無需切換物件／OCR／條碼模式，就能在下方讀到可辨內容；移开後不留下誤導結果。1秒是穩定取樣門檻，不是辨識完成時限。價值取決於目標切換不誤掛、回看可少等、操作比手動拍照順手，且持續使用的耗電與用量可接受。

當前未知：中央ROI能否在手持晃動下形成穩定目標；相似包裝／背面是否誤命中；移開時能否迅速隱藏；雲端晚回與背景返回是否污染畫面；合成圖成功能否轉為真實包裝文字／條碼；近似匹配與清晰度門檻尚無實測基線。原生Pro最小路徑已成立；自然續期在下方C合成測試已驗證一次，真實取景耗電仍未驗證。

本節於C核心實作開始後、實機相機啟動前补強測試理由；不是聲稱更早已知道門檻可行。先前C計畫已在實作前保存範圍與驗收，此次補足因果與決策依據，不扩大功能。

## A→B→C動機鏈（2026-10-09回顧補記）

原始關鍵疑問是「個人原生iPhone能否正式使用既有Pro」，因此先測最小登入而非先造完整App。A外部browser探針用無帳戶回呼隔離iPhone背景生命週期；失敗時只能說該路徑需回前景，不能否定全部原生方案。A2改系統認證視窗，讓相同loopback在2／45秒自動完成，才有理由進B；證據[PHASE_A](PHASE_A.md)。

B以真OAuth、model目錄、單張合成圖和冷啟動，逐一驗身份權限、模型可見是否真的支援image/none、串流完成與會話保留。先前缺診斷導致停止原因不明；後續依序修空行分隔、用安全細診斷定位缺Content-Type，最後response.completed與正確輸出成立；保留[PHASE_B](PHASE_B.md)失敗歷史，不把HTTP200視為成功。

C現在才處理真相機體驗：B證明付費／登入／模型路徑，沒有證明手持穩定、物件身份或延遲體驗。每一類C測試就是填補這些證據缺口，而不是為checklist增加測試。當時自然refresh／撤銷尚未測；C後來驗證自然refresh一次，撤銷仍未測。

## 設計與範圍

預設畫面改為相機日常入口，帳戶放獨立設定；首次按開始才要求camera permission，並告知中央稳定區域會單張送到已授權ChatGPT方案。本人選安全物品前不自動啟動真相機或送房間／人臉／私人文件。

相機畫面只在本機；以固定直向中央ROI取低頻樣本，分析區域像素與Vision特徵，不能只看陀螺儀。穩定約1秒且清晰、可信目標才編碼一張JPEG；全域最多一筆在途，最低送出間隔，無無限重試。相似但不確定的物件不命中快取，背面新目標。目標離開／變動立即隱藏，回看需重新穩定及嚴格匹配；快取有容量與存活時間，僅session memory。

Pro回答嚴格解析名稱、文字、條碼三欄；同時顯示在固定底部。未完成／查無／錯誤靜默；設定頁可查非敏感stage/code/HTTP/耗時。圖片不存檔、相簿或log，一般模型文字只解析成結果放memory。背景／開設定停止相機和新請求，取消inflight、清快取及匹配狀態，拒絕晚回；回前景需重新穩定。

## 驗收

離線fixtures涵蓋穩定1秒、A→B→A、近似不同物件不誤認、方向／旋轉、相機不動但ROI物件移動、模糊／空場靜默、背景重置、single-inflight、取消／超額停止、晚回不誤掛、TTL與容量。使用非敏感合成圖驗證新JSON結果pipeline；實際模型請求限必要且有理由，先檢查舊請求結束。

編譯與指定實機安裝、保存會話復用；真正相機端到端及首結果／cache延遲需本人選安全物品與第一次permission。準備完成再一次交接操作，其他文檔／離線工作繼續。模型延遲加在1秒穩定之後，不承諾1秒完成。

## 未承諾項目

沒有通用物件辨識或所有視角認回的精度保證。門檻是保守初版，需實機調整；不跨面、不查商品資料／百科、不分享／商業化、不扩其他模型。自然refresh與正式revoke分開記錄，未實測不假稱完成。
