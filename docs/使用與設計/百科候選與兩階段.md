# 百科候選與兩階段設計

本機 Build71 整合中：P22／W6、schema17／2、input3；尚未封裝。產品驗證範圍見[公開摘要](../驗證與建置/Build70公開驗證.md)。

## 第一階段與公開查詢

第一階段 P22 看圖片，產生中央主體名稱、兩三句簡介、忠實原文與獨立搜尋實體。`central` 是照片主體，`related` 是有依據的品牌／系列等關係，`text` 是原文中的獨立公開主題。中央不確定不應壓掉有根據的獨立文字主題。原文證據保持原語；可靠繁中名稱不必逐字出現在 OCR。

App 檢查欄位、公開查詢安全性、原文引用及既有准入條件；v17 正式中央 ID 仍要求 0。純排序測試用其他 ID 不代表正式輸入放寬。本機不以頁名、排列位置或字串命中裁定 `same_entity`。

## 完整實體查詢（延續 P21）

AI 按語意分出產品、品牌、系列、製造商或公開文字主題；正式名稱的空格、標點、型號保留，App 不依空格拆詞。品牌不是產品 alias，無證據不補公司或品牌。書名可為中央 product；有足夠公開線索的作者可為 text/person、relation none，沒有 author_of。

每個已接納實體依完整名稱在本機選站；假名選日文、韓文選韓文，漢字／無法判定維持中文，其他語言採 Apple NaturalLanguage 高信心且固定支援站點。最多兩站、中央優先，超過站點預算明列略過。第一個去重 alias 跟隨實體站點，仍只做精確標題；每站一次批次，合計最多四實體／八標題。剩下最多兩個全文查詢名額，先查未獲非轉址同名頁的中央，再按其他實體順序；只有轉址者仍可全文搜尋。名稱及 alias 是同一實體的完整詞組，不截成字詞。這不保證所有實體／alias 都有全文名額。

頁面保留中央優先，再涵蓋不同實體，最多五個不同 wiki＋pageID；剩餘依既有搜尋排名補入。API index 決定同批排名，缺值／同分按 page ID；精確、轉換、轉址或排名皆非身份證明。診斷介面可回傳各項查詢與完整映射鏈，不自動記錄資料。

schema17 名稱允許帶空白的副標題冒號，其他既有敏感／來源限制保留；v14～v16 不改。這是純名稱准入，也適用既有 v17 卡片的連結解析，不改寫舊資料或自動外送。

## 有界摘錄與一次文字核對

總蒐集期限二十秒，最多四個查詢加五個原文摘錄及兩個中文對應頁請求、五個最終來源；每次全文搜尋深度仍為三筆。送入模型時每頁最多三段，每段最多 400 Unicode scalars、每頁最多 1,200、合計最多 6,000；不相關導言可縮為 160。正文段落以所有已接納實體的完整名稱、aliases 及原文依據選取，包括 related 品牌／公司。第一階段原文選取總預算 1,600 scalars，`text_is_partial` 表示是否縮減。資料仍是局部摘錄，不能以未出現在摘錄推論不存在。

前兩個優先候選若是外文頁，既有摘錄請求一併取得中文 langlink；只有安全且標題／URL 對應的中文頁才另取摘錄，最多兩次。中文與原文成對合併後仍共用五名額，去重使用 wiki＋pageID，不把同數字 ID 當同一頁。中文無頁、取得失敗或無效則保留原文；不搜尋自行翻譯的名稱。

第二階段 W6 沒有照片或瀏覽工具。它優先選有摘錄證據支持的中央主體頁；頁名／別名／轉向只是查找提示。沒有充分本體支持時，才考慮既有品牌、系列、持有公司、製造商或獨立公開文字主題。

支持的商品→品牌關係，加上同一品牌的明確持有證據，可支持 `brand_owner`，不要求公司頁逐一點名該商品系列；持有不等於製造。`contextual` 指原文提及的獨立主題，不改成主體身份，保留原主體名稱與主要搜尋並附加背景。

每次自動流程或明確手動續做最多一次文字請求，不自動重試；輸入上限 128,000 bytes。原始第一階段 JSON 保存在本機，第二階段 `raw_stage_one_json` 固定 `null`，避免重複。引用須是所選摘錄中的逐字連續原文，來源 ID／URL／引用完整性可驗，模型語意與每句事實仍需品質驗收。

外語來源原名與 URL 保留，標示語言／既有關係，點擊開啟實際原文頁；中文標題繼續繁體顯示。input_version 3 各來源新增 language；P22 保持，W6 要求語意及關係正確性高於中文偏好，並沿用 search_name 提供同主體的通用中文搜尋名，沒有可靠中文名稱就保留原名。程式只讀該欄位，不翻譯或猜測語言。模型、schema17／2 形狀及五候選預算維持；最多兩個原文站加中文站、十一個請求。跨語言候選仍須由 AI 核對，不因語言連結便宣稱商品、品牌與母公司相同。

## 簡介顯示

Build69 卡片、重開與一般分享直接使用既有流程選定的 AI 簡介，不作語言分類、字形轉換或語言回退。沒有有效第二階段時保留第一階段；有效第二階段通常替換簡介，contextual 依原規則合併兩段非空內容。空值、失敗、來源／引用校驗與 stale attempt 保護維持；不產生缺少中文或初步中文回退提示。P22／W6 仍要求簡介繁中，但 AI 回外語時會如實顯示。原始 JSON、OCR、名稱、引文與原文連結不改寫。

## 保存與取消

同一卡片保存兩階段資料，以 record／attempt 身份與狀態保護晚回覆。新結果只更新顯示投影，不改寫第一階段原始回覆。舊卡不補查，W1／W2／W3／W4 舊請求仍可讀。

切背景依既有有限背景額度續行，到期與設定等停止路徑維持取消規則，詳[背景辨識](背景辨識與中斷.md)。`submitted` 只表示本機開始交送，不證明伺服器收到或回覆；沒有保存 modelResponse 也不能直接推論伺服器沒有回覆。

手動續做只在目前第一階段成功且有適用搜尋實體、第二階段未完成時開放。保存的 record／attempt、原圖與第一階段 JSON 不變，每次續做建立新的 runID 及可選 runNumber；舊紀錄缺少序號按第一代處理。已完成無匹配／證據不足不催重試，沒有可靠完成資料的舊卡保守標為未完成，但讀取不觸發任何請求。
