# 百科候選與兩階段設計

適用 Build 60，產品提交 `04f50d340e4357ed6d9a2265f56f2510be0e9b00`。完整模型指令、schema 與輸入見[AI 總表](../目前AI完整指令與Schema.md)。

## 第一階段與公開查詢

第一階段 P20 看圖片，產生中央主體名稱、兩三句簡介、忠實原文與獨立搜尋實體。`central` 是照片主體，`related` 是有依據的品牌／系列等關係，`text` 是原文中的獨立公開主題。中央不確定不應壓掉有根據的獨立文字主題。原文證據保持原語；可靠繁中名稱不必逐字出現在 OCR。

App 檢查欄位、公開查詢安全性、原文引用及既有准入條件；v17 正式中央 ID 仍要求 0。純排序測試用其他 ID 不代表正式輸入放寬。本機不以頁名、排列位置或字串命中裁定 `same_entity`。

## Build 60 的本體優先候選

在原最多三個查詢額度內，合規中央名稱與最多兩個去重別名先共用一次精確標題查找。採 API 回傳的繁簡／正規化／轉向映射保留命中的有效頁；缺頁、消歧義與無效頁排除，轉向鏈有界。

有精確候選時，另兩個查詢用於其他實體；找不到時，餘額先做中央全文搜尋，再查一個其他實體。沒有合規中央時沿用最多三個全文查詢。這個取捨可能少一個相關實體搜尋，未增加網路預算。

精確候選先保留；搜尋結果中主體名稱相符的標準頁也先考慮，再讓其他查詢各保留一個不重複頁，最後補足最多三頁。每次搜尋依有效 `index` 升冪排序，缺值／同分依 page ID 保持可重現。陣列先後不是 API 相關度，也不是語意證據。

## 有界摘錄與一次文字核對

總蒐集期限二十秒，最多三個查詢加三個摘錄請求、三個來源。送入模型時每頁最多三段，每段最多 400 Unicode scalars、每頁最多 1,200、合計最多 3,600；不相關導言可縮為 160。第一階段原文選取總預算 1,600 scalars，`text_is_partial` 表示是否縮減。資料仍是局部摘錄，不能以未出現在摘錄推論不存在。

第二階段 W4 沒有照片或瀏覽工具。它優先選有摘錄證據支持的中央主體頁；頁名／別名／轉向只是查找提示。沒有充分本體支持時，才考慮既有品牌、系列、持有公司、製造商或獨立公開文字主題。

支持的商品→品牌關係，加上同一品牌的明確持有證據，可支持 `brand_owner`，不要求公司頁逐一點名該商品系列；持有不等於製造。`contextual` 指原文提及的獨立主題，不改成主體身份，保留原主體名稱與主要搜尋並附加背景。

最多一次文字請求，不自動重試；輸入上限 128,000 bytes。原始第一階段 JSON 保存在本機，第二階段 `raw_stage_one_json` 固定 `null`，避免重複。引用須是所選摘錄中的逐字連續原文，來源 ID／URL／引用完整性可驗，模型語意與每句事實仍需品質驗收。

## 保存與取消

同一卡片保存兩階段資料，以 record／attempt 身份與狀態保護晚回覆。新結果只更新顯示投影，不改寫第一階段原始回覆。舊卡不補查，W1／W2／W3 舊請求仍可讀。

App 非 active、設定／相簿等停止路徑可能取消第二階段，具體以程式生命週期為準。`submitted` 只表示本機開始交送，不證明伺服器收到或回覆；沒有保存 modelResponse 也不能直接推論伺服器沒有回覆。既有單筆取消原因未知，本輪沒有改取消策略或重新操作裝置驗因。
