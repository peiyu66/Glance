# 背景辨識與中斷

適用已完成本機驗證並覆蓋安裝到Air的Build62候選；尚未啟動或驗收實機。舊版60立即取消百科的行為見[歷史說明](../歷史/Build60-61非active取消.md)。

## 一次明確操作能延續哪些工作

在前景按開始、重試保存圖片，或完成當次選圖後，取得穩定圖片的辨識可在有限背景時間內繼續。進入inactive／background會停止相機與尚未完成的選圖載入；已保留這次辨識的工作不因狀態切換立即取消。

App使用一般`beginBackgroundTask`延續正在處理的整段流程。若第一階段在背景完成，仍可接續維基百科查詢並發出同次的第二階段文字AI請求。沒有增加新拍照、第三次AI或自動重送；第二階段查詢與輸入上限保持既有值。

系統決定是否提供時間及何時到期，不能保證固定秒數或一定完成。既有第一階段120秒、第二階段70秒應用期限仍有效；不因切換前景／背景重新計時。工作全部結束時釋放背景額度，到期則撤銷後續階段准入、取消相關工作並收尾。

Apple文件：[延長App背景執行時間](https://developer.apple.com/documentation/uikit/extending-your-app-s-background-execution-time)及[ScenePhase.inactive](https://developer.apple.com/documentation/swiftui/scenephase/inactive)。這不是長時間背景服務，也沒有背景相機。

## 回到前景與重開App

短暫切出後，仍存在的attempt／run繼續收尾，不會被誤標為已中斷。回前景不自動重送、不自動重開鏡頭；下一張需再按開始。冷啟動讀取歷史時，沒有活躍工作的pending會修復為中斷，讀取舊紀錄本身不補查百科或重送AI。

第一階段未成功的卡標示「辨識中斷，尚未完成」，保存的圖片可手動再試。第一階段已成功時卡片仍可瀏覽、JSON與分享；百科未完成不把整張卡改成辨識失敗，正常卡片不新增百科成功／失敗／處理狀態文字。

背景到期／不可用、一般期限、撤回同意、換帳戶、手動停止、刪除與替換使用分開的本機原因。晚回覆必須仍符合record、attempt、run及同意／帳戶，不能覆寫新嘗試或已刪紀錄。本機「交給傳輸」只表示本機步驟，不證明服務端已收到。

## 同卡刷新

卡片操作列按JSON、圓圈刷新、分享排序；輔助使用大字體時移到同卡下一列。刷新使用該卡已保存的JPEG，跳過相機與停穩取圖，從第一階段重新辨識，不依賴相簿原圖仍存在。

刷新整段進行期間鎖定其他刷新、開始辨識與相簿輸入。等待或失敗時保留上次成功顯示與其JSON／分享來源，並提示目前顯示舊成功結果。新第一階段成功後才換成新結果，不混用舊第二階段來源。完成、失敗或背景到期會釋放忙碌鎖。

沒有保存圖片時，按鈕停用並顯示原因，不送空圖。結果保存失敗會保留記憶體結果及保存錯誤；重試保存只寫回資料，不重送網路。

## 驗證範圍

60個背景／刷新控制器斷言通過，涵蓋背景第一階段接第二階段、各階段到期、舊到期callback、短暫inactive、前景重讀與回寫競速、替換舊run、失敗保留及缺圖。另有核心保存／重啟案例及一般／大字體UI。都是封鎖真網路的合成測試；實機時長與真模型品質仍待相應授權與實測。
