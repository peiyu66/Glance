# Glance 開發指南

本文件供開發與維護使用。README 說明用途、操作與使用成本；測試方式、工程模式及證據限制集中於此。新增文件採繁體中文，保留必要程式與 API 名稱。

## 環境與建置

- 最低 iOS 17，開發工具 Xcode 27。
- 以 `Glance.xcodeproj` 的 `Glance` scheme 建置；個人 iPhone 簽署自行設定，憑證不得提交。
- 不需裝置的整合建置：

```sh
xcodebuild -project Glance.xcodeproj -scheme Glance -sdk iphonesimulator \
  -configuration Release -derivedDataPath /tmp/Glance-derived \
  CODE_SIGNING_ALLOWED=NO build
```

## 工程啟動旗標

在 Xcode scheme 的 Run arguments 設定。不得混用模式，也不得因合成測試通過就自行登入、取景或送模型請求。

| 旗標 | 用途與界線 |
| --- | --- |
| `--camera-live-current` | 一般預設管線的相容工程旗標；連續取景、保留卡片與簡介，冷啟動待開始，最多 3 次辨識嘗試。這是工程預算，不是正式方案額度。 |
| `--camera-live-fixture` | 生成影片走正式影格控制器、原生配準與 mock SSE，無真相機及真模型流量。 |
| `--camera-summary-ui-fixture` | 正式閱讀卡片、暫停閱讀與歷史列表的合成布局，含最大字體、原文展開、捲動及選讀途中加入新答案。 |
| `--camera-first-capture` | 保留的單張取景工程驗證，須本人按開始，最多一筆。 |
| `--camera-first-capture-fixture` | 單張管線的合成驗證。 |
| `--camera-first-capture-generated-real` | 會送出生成影像的真實模型工程驗證；不可當作離線測試或自動執行。 |
| `--camera-legacy` | 明確選擇舊管線作特殊測試；不屬普通入口或本輪新管線驗收。 |
| `--camera-trial-once` | 舊管線的一筆真實影像驗證，仍須本人按開始。 |
| `--mock`、`--camera-local-fixture` | 舊示範與生成卡片 matcher 檢查，不能替代目前 live 驗收。 |
| `--siwc-validation` | 帳戶驗證頁；網路、登入及憑證操作依本人授權執行。 |

其餘舊的獨立診斷模式保留供追溯，不代表候選追蹤／認回策略已採用。**普通無旗標入口已採新管線**；`CameraPipelineMode.resolve` 只在明確工程參數下選舊管線或單張模式，選路本身不啟相機。無參數冷啟動須核對 `cameraPipeline=live-current`、`explicitCameraModeArgument=false`、相機關閉、0/3 與無在途／待送。

逐步取景、送出及取消流程見[取景與辨識流程](取景與辨識流程.md)。

## 資源行為與驗證清單

最後讀碼核對：2026-10-10，保留結果與 AI 簡介版，普通預設入口（`--camera-live-current` 相容）。README 必須跟隨下列行為的實際變更更新；此清單不授權新增真實流量或裝置操作。

- [ ] 成功回覆保存：episode 結束後的首答仍入史、依送出序號選最新、較舊回覆不能蓋新；空值／失敗不蓋成功，最多三筆。選讀歷史時新回覆不得重置捲動或切換答案。
- [ ] 入口與生命週期：冷啟動待開始、手動暫停保留完成紀錄、inactive／背景／設定清空、前景恢復與程序重建預算；測舊回覆不復活。
- [ ] 相機與本機處理：記錄解析度、取樣節奏、品質門檻、OCR／原生配準路徑、監看與診斷寫入；區分取樣率與感光器／預覽幀率。
- [ ] 網路與額度：驗明何時凍結影像、單筆在途、最新待送意圖、失敗重試政策、送出嘗試計數與上限；確認 cap 不被誤寫成停相機或所有 HTTP 上限。
- [ ] 取消與服務端：測暫停、背景、任務取消及晚回；不能把本機取消寫成服務端立即停止或免計費。
- [ ] 帳戶與成本保護：保留方案 scope 與本機確認門檻、按需 refresh／models、無 API key fallback；官方額外點數開關仍由本人確認，不把 attestation 當成 API 驗證。
- [ ] 文件與證據：同步 README 五狀態表、最後核對日期／版本和未知項；詳細結果保存於私人驗證紀錄，公開只寫可公開的摘要。工程預算變更尤其須更新文件。

本次讀碼：`CameraCapture.start` 使用 1080p session；影格 callback 每 0.25 秒最多分析一張，先裁切與品質檢查。平均亮度需介於 0.045 與 0.97，對比方差大於 0.003、邊緣分數大於 0.03。品質失敗不做後續 JPEG／發送；真實暗光與雜訊未量測，不能保證所有看似無效畫面都不觸發。

目前 live 模式走 `prepareLiveFrame`／`prepareFirstCapture`，不做舊 `prepareTarget` 的 OCR／saliency／條碼辨識；品質通過才做原生幾何配準，完全相同指紋有捷徑。Vision／Core Image 實際由 CPU／GPU 等硬體分工，未量測占用。250 ms 本機 watchdog 及最多每秒一次安全摘要寫入不是網路輪詢。

符合新辨識條件才呼叫 `SIWCController.recognize`，按需更新 token，空模型目錄才讀 `/models`。取景路徑沒有閒置 refresh 計時器或辨識自動 retry。`URLSession` 使用 ephemeral 設定，request timeout 30 秒、resource timeout 120 秒；不能把逾時設定當成黑畫面、暫停或伺服器立即停止的保證。登入／登出等明確帳戶操作有自己的網路流程，不受辨識三次預算控制。

目前未量測：每小時電池下降、熱狀態、CPU／GPU、實際 sensor／preview fps、上下載 bytes、每張影像的服務端額度、取消後服務端消耗、各網路環境及長時間運作。未來測量應先定義要支持的決策、裝置與版本、期間、停止條件及可接受範圍；不能由合成處理延遲換算電池或費用。

## 資料與驗收界線

公開 repository 不提交照片、本人辨識內容、token、帳戶或裝置識別、簽署素材、私人路徑及原始日誌；`.gitignore` 不能代替內容審查。fixture 應只使用可公開的生成素材，必要安全摘要只記錄欄位數、狀態與時間。

名稱與簡介採 `zh-Hant-TW`，原文和條碼維持原樣；舊三欄答案可解析為空簡介，空／null 簡介不顯示，錯誤型別拒絕。本人已確認本輪 UX 可用，簡介品質延後，離線契約不等於模型正確率保證。
