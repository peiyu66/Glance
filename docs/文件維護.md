# 文件維護規則

2026-10-20 依使用者指定整理。上層文件保持當前版本可用說明；已退出現有作法的文件收納下層，混合新舊的長文件保存舊全文後重寫當前入口。

## 分類

- 使用與設計：當前操作、資料流、限制與兩階段設計。
- AI：唯一完整總表、實際匯出契約及可重算來源。
- 驗證與建置：本版摘要與本機歷次版本報告；每項結果標明版本與驗證層級。
- 歷史：退役方案、研究、舊指南、整理前的計畫／交接與README全文。

搬移時維持原文事實與時間，不把歷史「未安裝」直接改成「已安裝」。改寫相對連結使其仍指向原證據；原位置、現位置及前後雜湊另存本機搬移清單。原始測試資料保留原位，沒有永久刪除。

## 正式入口與公開投影

本機主工作樹 `docs/README.md` 是正式入口。產品候選工作樹指向此入口，保留自身版本報告。公開文件分支從已核實公開main建立，只提交本輪可公開文件；未把候選工作樹的產品歷史、私人紀錄或絕對本機路徑一併推送。

本次完整盤點為主工作樹126份、候選95份Markdown（含歷史證據內文件）；同路徑只有10份。每份原文件均由本機完整索引記錄去向，不以同名就互相覆寫。原文已下移的上層路徑只有在仍是正式入口時才重建當前內容。

## 更新時要核對

同時核對開發版本、裝置已安裝版本、公開安裝版及公開來源基底。AI改動須從實際程式匯出完整prompt/schema與輸入範例；舊例若已不適用，移入歷史。標明測試是本輪執行或沿用、真實或合成、已證實或未知。

新增文件連結須存在；歷史失效的臨時路徑保留文字出處並標示，不假造新證據。文件提交前檢查整段待推提交，只容許本輪文件，不夾帶產品、簽署檔、帳戶或使用者資料。不要由文件整理開啟新的裝置測試或已結案事故。

## 現行文件文風

功能、決策與驗證結果採直接客觀敘述，省略不必要的作者或決策主詞，不以個人第一人稱代筆。必要的OpenAI、模型名稱與資料流保留；原文引用、完整實際prompt／schema及不可變歷史證據不因文風改寫。使用回報與自動化測試分開標示。
