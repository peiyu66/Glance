# 取景與辨識流程

最後核對：**2026-10-10（台灣時間），普通啟動採新管線整合版**。本文對應一般無參數啟動的流程，冷啟動維持待開始與三次預算；`--camera-live-current` 保留為相容工程旗標，舊管線必須明確指定 `--camera-legacy` 或相應舊測試模式。程式由 `f641d9f` 與遠端中文文件 `6d214fd` 整合；公開版本以包含此文件的 Git 提交為準；本輪整合來源與建置、裝置回歸及安裝基準均有保存。

## 先看這段

**「3 張」是最多 3 次辨識送出嘗試，不是相機只擷取 3 張，也不是 3 次成功。** 取景期間，相機持續供應影格；App 最多每秒挑約 4 張做本機分析。畫面穩定滿一秒、有剩餘名額且上一筆傳輸已結束，才將中央影像壓成一張 JPEG 送給 AI。

辨識期間可以移動鏡頭。App 會繼續判斷新畫面，最多保留一個最新的待送意圖；舊回覆不會被冒充為新物件結果。已經有效顯示過的卡片則保留，離開原畫面時標示「上次辨識」，直到下一筆有效結果取代。按暫停會停止取景並清空卡片。

三次用完後仍有相機、預覽及本機分析成本，**不會自動停相機**。不用時請按「暫停」。五種 App 狀態的成本摘要見 [README](../README.md#執行成本與資源使用)。

## 從開始到暫停

### 1. 按「開始取景」

App 先確認已登入、具有方案權限，且本人已勾選「官方額外點數已停用」，再檢查相機權限。未通過時不開始取景。此勾選只記錄本人確認，不能代替官方開關的實際查核。

相機採後置廣角、1080p 預設，能支援時使用低延遲防手震，否則關閉該防手震模式。冷啟動不自動取景；若先前正在取景而切背景，回前景會恢復。手動暫停會取消這個恢復意願。

### 2. 持續取樣，在本機先篩選

相機 callback 會持續收到影格；距離上次分析不足 **0.25 秒**的影格直接略過。分析最多約 **4 次／秒**，實際可能更少，並不代表感光器與預覽也被設為 4 fps。積壓的影格會被丟棄，不排隊慢慢處理舊畫面。

每個分析樣本先取畫面中央的正方形：邊長是相機影格短邊的 **78%**，縮小到最大約 **768 × 768**，不放大較小來源。一般直向 1080 × 1920 來源相當於先取中央約 842 × 842 再縮小。這是相機畫面的裁切，**不是手機螢幕截圖**；不包含 App 卡片或按鈕，也不存進相簿。

App 用小尺寸 RGB 樣本檢查亮度、對比及邊緣。太暗、太亮、太平坦或缺乏細節會中止這張樣本的後續處理，重新等待有效畫面。這些檢查已經會用到本機運算，不能把「沒有送 AI」當成「沒有耗電」。

### 3. 先容忍小幅手震，再判斷是否換景

目前模式不先做本機文字辨識、條碼辨識或物件身份搜尋。它以 Apple Vision 的影像配準，比較現在的中央畫面與這段連續觀看的參考畫面：先對齊小幅位移、轉動及透視差，再檢查內容是否仍接近。

配準只比較中央影像內側區域，四邊各留 **1/12** 的邊界；在 768 方圖上，各邊約 64 像素，內側約 640 × 640。若配準後四角中最大的位移超過這個邊界、重疊範圍不足、配準失敗，或內容差異分數大於 **0.035**，會視為新的連續觀看段落，重新計時。

因此沒有「移動 X 公分」或「轉動 X 度」的固定界線，也沒用陀螺儀判定。數值是影像座標和工程差異分數；不是物件身份保證。相機不動而物品被換掉，也可能形成換景；外觀很接近的物品仍可能難以區分。

### 4. 有效且連續穩定滿一秒，採納一次意圖

對齊後的指紋同時與這段觀看的起始樣本、前一個樣本比較，較大的差異必須不超過 **0.035**。持續到樣本時間累積 **1 秒**，才建立這段畫面的辨識意圖。

畫面品質不合格、差異超標、配準宣告換景、影格順序錯誤、影格已舊或間隔超過 **0.75 秒**，都會使連續性失效。一個有效的新樣本可作為新一秒計時的起點。這不是「按下開始一秒後必定拍照」；手震、低品質、運算延誤會延後它，AI 回覆還需額外時間。

目前這條管線沒有獨立的「soft uncertain」與「hard change」雙層狀態：不確定或失效就撤銷目前送出／新結果資格，重新取得穩定性。介面仍保留先前已提交的卡片，這個閱讀策略不代表舊影像仍有資格送出或新回覆仍可顯示。

每段連續觀看只採納一次；持續對著同一畫面不會每隔一秒重送。移開後再對回來是新的段落，可以消耗下一次名額；目前 live 模式沒有跨離場快取認回。

### 5. 有空位時，才製作並送出最新單張影像

同時最多 **1 筆辨識工作在途**。等待舊請求時，新的穩定畫面仍可被採納，但最多保留 **1 個最新待送意圖**，不保存一串過時 JPEG。

例如 A 還在辨識，B 穩定滿一秒後進入待送；若又移到 C，B 的待送資格撤銷，C 也必須重新穩定滿一秒。A 結束後，在 C 的下一張有效新影格到達時才可能送 C。畫面移動本身不會取消 A 的網路傳輸，A 的過期答案會被丟棄。

有空位、未被錯誤阻擋且仍有預算時，用**此刻最新的中央影像**壓成 JPEG，品質參數 **0.82**。送的是未經配準扭曲的中央方圖；內側配準區域只供本機判斷。壓縮完成後還要確認它仍屬目前段落、是最新觀測影格，且年齡不超過 **0.75 秒**，才登記一次送出嘗試。

JPEG 編碼失敗不扣次數，但同段落不會因此自動重試。若編碼後影格已過期，該張不能送；之後有新有效影格才可能重新取得資格。新的網路請求不使用舊管線固定四秒的發送等待。

### 6. AI 收到什麼，又何時顯示

辨識請求使用原生方案授權，固定模型 **`gpt-6-luna`**、**`reasoning.effort=none`**；先確認帳戶模型清單支援。送出內容是一張 base64 JPEG，加上要求依可見證據回答的文字指示；沒有錄影、聲音、相簿內容或完整螢幕截圖。必要時會先更新即將過期的授權，模型清單為空時讀取清單，這些也會連網。

要求模型只回傳四欄 JSON：

| 欄位 | 用途 |
| --- | --- |
| `names` | 簡短物件名稱陣列，採台灣繁體中文。 |
| `summary` | AI 整合可見證據的短簡介，最多三個短句；不是逐行翻譯。證據不足可空白。 |
| `text` | 清楚可讀的原文陣列，保留品牌、型號、文字與原本語言。 |
| `barcodes` | 清楚可讀的條碼值陣列，保留每個數字與前導零。 |

指示不查網路、不補外部資料、不猜模糊品牌／型號／隱藏文字，也不遵從影像內的指令。藥品只概述清楚可讀標籤支持的資訊，不猜療效、劑量或適用性，不提供個人服用建議。這是輸出要求，**不能保證模型每次都遵守**；簡介品質仍待後續改善。

HTTP 成功還不等於完成。App 必須收到 SSE 的 `response.completed`，成功解析內容，確認請求仍屬目前段落與本次取景世代，最後再等**回覆完成後的一張有效新影格**確認連續性，才把新卡片顯示出來。只收到半段文字、過期回覆或空答案都不能成為新的卡片。

已有有效卡片時，換景、等待、空答案或失敗都先保留，離開原段落加上「上次辨識」。新的有效結果整張取代它；相同內容保留捲動位置，真正不同內容回頂端並收合原文。捲動與展開只是閱讀，不發送 AI。

### 7. 暫停、背景與結束

按「暫停」會清除自動恢復意願、停止相機、取消 0.25 秒監看、要求取消在途工作，並清除卡片和本機暫存。相機停止是在序列佇列執行，可能仍有已排隊 callback 收尾；世代檢查會拒絕它們。

離開前景／切背景或開設定也會停止取景並清除結果，但保留先前的取景意願，回前景／關設定時可能自動恢復。App 程序終止才停止該程序的全部工作，不能把切背景等同結束 App。

取消是本機要求，不保證已送達的伺服器工作立即停止、退回額度或免計費。只有舊工作完成、錯誤或取消回傳到本機後才釋放傳輸槽；不是發出取消就立即釋放。程式沒有服務端停止確認機制，所以取消／逾時後若又送新請求，舊服務端工作仍可能繼續，不能保證服務端絕不並行。

## 三次上限到底怎麼算

- **開始計數點：** JPEG 已完成、影格時效與目前段落檢查通過，`startRequest` 登記工作時加一，畫面顯示「已送 1/3」。它早於實際授權更新、模型清單與網路傳輸，故準備失敗也可能已占一次。
- **不以成功計數：** 錯誤、逾時、空答案、舊答案丟棄或取消都不退還已占用名額，不能稱「成功辨識三張」。相機收到或本機分析影格不會扣名額。
- **暫停不重置：** 同一控制器內，暫停／開始、背景／前景及設定往返保留已用名額。整個程序重啟或控制器重建才得到新預算；不是帳戶每日限額。
- **達限仍在運作：** 不再採納新的辨識意圖或送圖，但相機、預覽、品質、配準、穩定判斷、監看及必要安全摘要仍運作。第三筆已在途的工作仍會收尾；最後有效卡片可繼續閱讀。
- **工程用途：** 三次讓目前有界驗收可涵蓋 A → B → A，不代表永久產品承諾，也不限制登入、授權更新等所有 HTTP 請求。
